# 科技重要度与收录边界复查计划（存量裁决清单）

日期：2026-09-27
范围：`data/techs.json` 全量 3876 条的 `importance`（1–5 档）与"是否算科技"两个轴
产出：一份可逐条裁决的**存量裁决清单** + 裁决落盘文件
明确不含：回写 `techs.json`、新增校验闸门、长期防漂机制（均为后续独立 PR）

## 1. 背景与实测现状

| 轴 | 当前状态 |
|---|---|
| importance | P1/P2/P3/P4/P5 = 225 / 1607 / 1264 / 697 / 83，P2 占 41.5% 明显偏厚 |
| 收录边界 | 库内无书面"什么算科技"定义；`kind`（工艺 1367 / 器物 1143 / 原理 714 / 制度 465 / 媒介 187）由早期关键词脚本猜出，`fix_kind.py` 一次性改判 119 条后仍有系统性疑点 |

判据来源：CONTRIBUTING §4 的"抽掉它，后面有多少条科技站不住"；§kind 五分类。本次不新造判据，只把隐含判据显式化并经你逐条验证。

## 2. 关键约束：结构信号被补边欠账污染（实测）

提名规则粗算过程中确认了一个必须先说清的事实：

- 全库 **2158 / 3876 条没有任何直接下游**（prereq 终点计数为 0）
- 且 **`pf == 0` 与"传递闭包下游 == 0"是同一批条目**（2158 条，逐条等价，已由 `adjud_lib.mjs --selftest` 断言）—— 所以"域内下游数"这类结构信号在本库里就是扇入换了个写法，不是独立证据
- 档位与"零直接前置引用"几乎无关：P1 = 34 条、**P2 = 827 条**、P3 = 737 条、P4 = 496 条、P5 = 64 条
- 22 个领域中 **15 个的"域内下游数中位数 = 0"**，这 15 域共 2946 条、含全库 P2 的 69%（1104 条）

结论：**扇入 / 下游数只能做"域内相对"提名，不能当档位判据**。上一轮已确认"标 1 却零入边"有两类病因（下游没把边指回来 vs 档位虚高），在边稀疏 56% 的当前状态下，用绝对数量筛会把接线欠账误判成标注问题。故：

- 结构信号只用于提名，且全部按域内相对位置计算
- 证据卡上"直接前置引用数 pf"与"域内下游数/排名"并列显示，并在卡片顶部标注该域"零下游条目占比"，使档位裁决不被接线欠账带偏
- 本计划**不改 prereq 边**（那是独立的一轮）

## 3. 方案：三段式（校准 → 提名 → 全量快筛）

### 3.1 第一段 · 校准批（100 条，2 批 × 50）

分层抽样，避免样本偏科：

- **按 22 域配额**：每域至少 3 条，剩余名额按域大小比例分配
- **每域内按（档位 × 是否引用 × kind）覆盖**：至少含 1 条 P1/P2、1 条 P4/P5、1 条 `kind` 为原理或媒介的条目
- **固定随机种子**，样本 id 清单入库可复现
- **规模口径**：100 条是各域下限（22 × 3 = 66）之上的抽样，不是穷举；若某域连自己的 3 条下限都凑不齐（如 `space_exploration` 只有 4 条 P1），该域全量纳入并如实标注

产出：
1. 你在 100 条上的真实裁决
2. 据此写 **《收录边界判据 v1》**——把"移出/保留标记"的裁决理由归纳成 5–10 条可操作判据（例如"具体驯化物种记的是产物而非驯化工艺本身→移出或并回工艺条目"）
3. 据"留在库里但你觉得该动"的比例得出**档位卡点**（见 §6）

### 3.2 第二段 · 规则提名 + 漏检验证

用第一段的判据把提名规则写成确定性脚本，通道与实测规模：

| 通道 | 规则（域内相对） | 实测 |
|---|---|---|
| 基石尾组 | P1 且（域内下游数 ≤ 本域 P1 的 20 分位 或 直接前置引用为 0） | 64 |
| 支柱尾组 | P2 且 域内下游数 ≤ 本域 P2 的 20 分位 且 < 全域中位数 | 208 |
| 疑被低估 | P3+ 且 域内下游数 ≥ 本域 75 分位 且绝对值 > 50 | 23 |
| 原理零引用 | `kind=原理` 且 被引总数为 0 | 100 |
| 孤岛媒介制度 | `kind∈{媒介,制度}` 且 零被引 且 零出边 | 7 |
| 高档无溯源 | P1/P2 且 `wikiEn` 为空 | 5（全库无 wikiEn 共 53 条） |
| 判据专项 | 按判据 v1 逐条转写的规则（如域/词形/物种名例外名单） | 待第一段后定 |

**漏检验证**：拿校准批 100 条当测试集，凡是你在第一段判了"改判/移出"但规则没提名出来的条目，逐条回推规则，直到漏检 ≤ 1/3。带漏检进全量是本计划要防的主要失败模式。

**通道有效性复查（2026-09-27 实跑后补）**：三条结构通道在本库边稀疏的现实下有系统性缺陷，第二段开工前必须先定口径——

| 通道 | 实测 | 缺陷 |
|---|---|---|
| 支柱尾组 | 208 | 规则含"域内下游数 < 全域中位数"，而 15/22 域中位数 = 0，该式在数学上永不胜出 → **这 15 域（2946 条、全库 P2 的 69%）一条都不会被提名**。208 条全部来自剩下 7 个域。 |
| 基石尾组 | 64 | "或 pf==0" 那一支是纯接线检查，与档位无关；它把这 64 条的成因混成了两类（见 §2） |
| 疑被低估 | 23 | 依赖下游数，同样只在边较密的域生效 |

结论：**结构通道只能当"接线欠账普查"，不能当重要度复查的主力**。主力应换成与边无关的信号：`kind` + 判据 v1 转写的词形/域规则 + `rf` + 同域同代档位秩（`tier_rank_pct`）。第二段派工时按这个优先级写规则，支柱尾组的 208 条继续裁（它是有效的接线清单），但不再宣称它覆盖 P2 档位问题。

### 3.3 第三段 · 全量快筛（门槛制，默认不锁死）

**启动条件**：校准批 100 条中你的"改判 + 移出"合计推翻率 > 20%。
- 若 ≤ 20%：说明存量质量高于抽样预期，**停在第二段**，只裁决提名池（约 400–500 条）
- 若 > 20%：跑全量快筛，3876 条按 22 域 × 档位分组、80–100 条一批（约 40 批），未裁决部分随时可停，清单里显式标"未覆盖范围"

快筛批与提名批的区别：快筛批只出**一行摘要**（名字 + 现档 + 域内相对位置）供你一眼确认，只有你标了"有疑问"的条目才展开成完整证据卡。

## 4. 证据卡字段

机械事实（全部从库里算，不派生观点）：

```
id / name / nameEn / wikiEn / 现 importance / 现 kind / category / era
year + year_basis / desc（原文）
pf = 作为他人 prereq 终点的次数
rf = 被引总数（prereq + related）
域内下游数排名（百分位）/ 绝对下游数 / 直接下游前 5 条
提名通道（含"被低估提名"这类反向通道）
```

不预填结论档，不给"模型建议档"——避免把裁决变成同意/不同意的锚定游戏。`kind` 若需参考值，只允许出现在卡片备注里且标明来源，不进判据。

## 5. 裁决界面与数据格式

**界面**：单文件 HTML（`scripts/adjudicate_review.html`），`file://` 直开，零服务器零依赖；进度存 `localStorage`，可中途导出 JSON。复用 `jev_boundary.html` 的评审页形态，但不依赖它的服务端。

**每条目两个控件**：

1. 是否算科技（三态）：`算科技` / `非科技但保留（另立标记）` / `移出主库`
2. importance：`维持` / `改成 1–5` / `证据不足挂起`
3. 备注：一句话理由；选"保留标记""移出""改档"时必填

**落盘**：

- `data/adjudication-2026Q4.json` —— 逐条记录 `{id, batch, channel, boundary_verdict, importance_verdict, reason, ts}`，可分批追加、可断点续跑
- `data/adjudication-2026Q4-queue.md` —— 给你和人看的汇总表（按通道 / 域统计）
- `docs/boundary-criteria-v1.md` —— 第一段产出的判据文档

## 6. 卡点与度量

| 卡点 | 判据 | 不过怎么办 |
|---|---|---|
| 校准批推翻率 | 改判+移出 > 20% 才启动全量快筛 | ≤20% 停在第二段并报明"全量未覆盖" |
| 提名规则漏检 | 校准批里你判"该动"的条目被规则提名 ≥ 2/3 | 回推规则，不带漏检进下一段 |
| 规则命中量 | 命中 < 5 条视为规则无效（可能是对判据的过拟合） | 改写成结构化规则（域 / 词形 / 例外名单），不用语义词 |
| 每批一致性 | 每批结束报"该批推翻率"，与上一批差 > 15 个百分点时提示判据可能已漂移 | 暂停并回看判据是否需要 v1.1 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 边稀疏使结构提名偏弱，真问题条目可能不在池里 | 判据专项通道 + 全量快筛兜底；本计划不改边，避免混淆两类病因 |
| 档位在域内是相对量，动一批会改变同域他人相对位置 | 本计划只出结论不回写；回写时按域整批重算扇入基线（`recalibrate_importance.py` 已在此位置），并先更新 `core-ids.json` |
| 模型二审在抽象判断上塌成常数（merger 102 子句全挤在 0.12–0.37） | 不引入任何自动改判；模型输出最多作为卡片备注参考 |
| 裁决中途你的标准发生变化 | 每批顶部显示判据 v1 全文；批次推翻率突变即提示，判据可升 v1.1 并标记受影响批次需重看 |
| "移出"意味着删数据， irreversible | 本阶段只写裁决文件不动 `techs.json`；回写时进 `data/research/` 存档 + 单独 PR，由你验收后再合 |

## 9. 并行分工与文件所有权（5 路）

执行期冻结在 `docs/superpowers/specs/2026-09-27-adjud-tooling-contract.md`（域分组、MetricRow、通道名、分片落盘、裁决页与快筛分批的具体形状），本节只记口径：

- **5 个会话共享同一个工作树**，因此：一个 shard 只有一个 writer；裁决记录**分片写、永不合并写同一文件**；任何代理不得 `git add/commit/stash`（暂存区会被别的会话带进它的提交）。
- 域分组按实测大小配平，A≈774 / B≈512 / C≈767 / D≈775 / E≈1048（合计 3876，两两不相交、并集为全库，由 `adjud_contract_check.mjs` 运行时断言）。**早期讨论里的"各组 722–775"是错的**（只加了 4 个域就当成全组），凡规模数字一律运行时推导，不写常量。
- 瓶颈是串行的两处：**你的裁决本身**（一次只能看一张卡）和**判据 v1**（必须从校准批的真实裁决里长出来）。5 路并行提速的是"出待审清单"，不是"替你裁"。若跳过校准批直接 5 路开裁，各会话对"什么算科技"的理解不一致，你会反复重新解释判据。
- 校准批 100 个 id 预留给漏检验证，任何组不得再裁一遍（否则漏检率没有测试集）。
- 回写 `techs.json` 不在这 5 路里，按 §7 的约定另开 PR 由你验收。
